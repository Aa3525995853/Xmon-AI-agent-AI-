## 二、关键缺陷详解

### 🔴 缺陷一：情绪触发过度侵略（CRITICAL）

**现象描述**：
当用户消息中包含负面情绪关键词（如"累"、"崩溃"等）时，主动情绪关怀系统会**完全覆盖**用户的实际意图。

**复现步骤**：
```bash
# 步骤1：用户正常询问
curl -X POST "http://localhost:3000/api/chat/text" \
  -d '{"message":"小梦，我叫什么名字？"}'

# 期望：回答"王富贵"
# 实际：得到一段关于"你真的好累"的情绪安慰
```

**根本原因**：
`proactiveService.detectEmotion()` 通过关键词匹配触发关怀，导致：
1. "我叫王富贵" → 被误判为包含负面情绪
2. 用户实际问题被完全忽略
3. 回复与上下文完全无关

**影响评估**：
- 严重损害用户体验
- 用户无法获得简单的事实性答案
- 系统显得"听不懂人话"

### 🟠 缺陷三：对话历史缓存问题（HIGH）

**现象描述**：
使用相同或相似的消息内容时，返回的回复高度相似，疑似缓存命中。

**测试用例**：
```bash

```

**观察结果**：

- 相似的开头问候语
- 相似的关心语句

**根本原因**：
1. API 端可能有响应缓存
2. LLM 的 few-shot 提示词可能影响了生成
3. 对话历史 `conversationHistory` 被用于上下文注入
