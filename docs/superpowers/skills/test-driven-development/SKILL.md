# Test-Driven Development（测试驱动开发）

## 概述

先写测试。看着它失败。写最少的代码通过。

**核心原则：** 如果你没有看着测试失败，你就不知道它是否测试了正确的内容。

**违反规则的字面意思就是违反规则的精神。**

## 何时使用

**始终使用：**
- 新功能
- Bug 修复
- 重构
- 行为变更

**例外（询问你的用户）：**
- 一次性原型
- 生成的代码
- 配置文件

想过"这次跳过 TDD"？停。这是合理化。

## 铁律

```
没有先写失败的测试就不能写生产代码
```

在测试之前写代码？删除它。重新开始。

**没有例外：**
- 不要保留作为"参考"
- 不要在写测试时"调整"它
- 不要看它
- 删除意味着删除

根据测试重新实现。就是这样。

## 红-绿-重构

```
┌──────────┐     ┌──────────────┐     ┌────────┐
│   RED    │────→│ 验证失败     │──否──→│ 回到   │
│ 写失败测试│     │ 正确失败？   │     │  RED   │
└──────────┘     └──────────────┘     └────────┘
                     │是
                     ↓
┌──────────┐     ┌──────────────┐     ┌────────┐
│  GREEN   │────→│ 验证通过     │──否──→│ 回到   │
│ 最少代码 │     │ 所有通过？   │     │ GREEN  │
└──────────┘     └──────────────┘     └────────┘
                     │是
                     ↓
              ┌────────────┐
              │  REFACTOR  │
              │   重构     │
              └────────────┘
```

### RED - 写失败的测试

写一个最小测试，显示应该发生什么。

**要求：**
- 一个行为
- 清晰的名称
- 真实代码（除非不可避免，否则不用 mocks）

### 验证 RED - 看它失败

**必须执行。永远不要跳过。**

```bash
npm test path/to/test.test.js
```

确认：
- 测试失败（不是错误）
- 失败消息符合预期
- 因为功能缺失而失败（不是拼写错误）

**测试通过了？** 你在测试现有行为。修复测试。

**测试出错了？** 修复错误，重新运行直到它正确失败。

### GREEN - 最少代码

写最简单的代码让测试通过。

不要添加功能、重构其他代码或超出测试范围"改进"。

### 验证 GREEN - 看它通过

**必须执行。**

```bash
npm test path/to/test.test.js
```

确认：
- 测试通过
- 其他测试仍然通过
- 输出干净（无错误、无警告）

**测试失败了？** 修复代码，不是测试。

**其他测试失败了？** 现在修复。

### REFACTOR - 清理

只有在 green 之后：
- 移除重复
- 改进名称
- 提取辅助函数

保持测试 green。不要添加行为。

### 重复

下一个功能的下一个失败测试。

## 常见合理化

| 借口 | 现实 |
|------|------|
| "太简单不需要测试" | 简单代码也会坏。测试只需30秒。 |
| "我之后再测" | 测试立即通过什么也证明不了。 |
| "之后测也能达到同样目标" | 后测 = "这做什么？" 先测 = "这应该做什么？" |
| "已经手动测试了" | 临时 ≠ 系统。没有记录，不能重跑。 |
| "删除X小时的工作是浪费" | 沉没成本谬论。保留未验证代码是技术债务。 |
| "这只是仪式，精神更重要" | 精神就是仪式。跳过仪式就是跳过精神。 |

## 红线 - 停止并重新开始

- 测试在实现之后写
- 测试立即通过
- 无法解释为什么测试失败
- 合理化"就这一次"
- "我已经手动测试了"
- "之后测也能达到同样目的"

**所有这些意味着：删除代码。用 TDD 重新开始。**

## 验证检查清单

在标记工作完成之前：

- [ ] 每个新函数/方法都有测试
- [ ] 在实现之前看着每个测试失败
- [ ] 每个测试都因为预期原因失败（功能缺失，不是拼写错误）
- [ ] 写了最少的代码让每个测试通过
- [ ] 所有测试通过
- [ ] 输出干净（无错误、无警告）
- [ ] 测试使用真实代码（除非不可避免，否则不用 mocks）
- [ ] 覆盖了边缘情况和错误

无法勾选所有框？你跳过了 TDD。重新开始。

## 最后规则

```
生产代码 → 测试存在且先失败
否则 → 不是 TDD
```

没有用户许可，没有例外。
